# Low-latency pre-start answers

`POST /api/pre-start/assistant-answer` accepts `{message, context?, contract?}` (message maximum 4,000 characters) and returns `{reply, links: [], contract}`. Without a contract, existing extraction/routing requests retain their protocol. Authentication, role policy and per-user limits remain in place. This endpoint does not create company-assistant conversations or run company search/tools.

Context is bounded to 12 messages of up to 1,000 characters, 22 known saved fields of up to 4,000 characters, a 600-character question, an optional edit intent and up to four pending values of up to 4,000 characters each. Pending values are unapplied proposals. Only user/assistant roles and known editable fields are accepted. Context is quoted data; historical answers must not be replayed as fresh updates.

## Confirmed conversational edits

The updated iOS conversation opts into `contract: "prestart-turn-v2"`. Its message is JSON containing `currentField`, `allowedFields` (key/kind), `transcript`, `priorAnswers` and `followUp`. The server validates allowed field keys before calling the model and sends a strict JSON schema constrained to those fields. The reply is a JSON string with `action`, `updates`, `target`, `editMode` and `question`. Every update contains `key`, `mode` (`answer`, `append`, `replace`), typed `value`, verbatim user `evidence` and `replaceEntire`. Actions are `updates`, `clarify`, `confirm`, `cancel` or `reopen`; non-update actions have no updates. Unused nullable properties are null.

One turn can supply up to four explicit changes, including both a current answer and an earlier correction. Booleans use boolean/null, counts use digit strings, and risks use one to six `{row,risk,action}` objects. Ambiguous trade speech asks a focused question. The known “four from height” homophone does not justify inventing a four-metre fall. Whole replacements exclude removed facts; partial replacements preserve unrelated rows/names.

The app validates the whole batch, reads the exact changes, and waits for approval before editing earlier or populated fields. Natural agreement applies the stored proposal without another model call. Rejections, different “yes, but…” instructions and cancellation cannot commit it. A changed manual form invalidates a pending proposal. New first answers retain normal automatic progression. The client additionally checks evidence, unsupported numbers/units and stale history; schema compliance alone does not establish factual correctness.

The app retains history during one form screen's lifetime, including assistant close/reopen and pause/resume. Changing form or leaving the screen discards the dialogue; reopening a saved draft still supplies its saved answers. History is not added to shared speech storage. Earlier corrections keep the interrupted question/follow-up, and an empty revisit request asks for the update before writing. Cancelling a pending correction preserves the form. Existing fast yes/no/count handling, microphone timing, model, playback and normal question sequence remain in place.

Uses the existing `OpenAI__ApiKey`. Optional `OpenAI__PreStartModel` defaults to `gpt-4.1-mini`, with 1,600 output tokens for v2 or 1,000 for legacy calls, no reasoning step or tools, and a 15-second provider timeout. V2 requires a model supporting strict Structured Outputs. Incomplete, refused, empty or invalid structured output is rejected. Logs contain model elapsed milliseconds only, never answers or credentials.

The app retains its microphone endpointing, next-question prefetch, local numeric/boolean rules and provider-specific voice cache. See `PreStartSpeech.md` for confirmation fragments and shared/private cache scope.

Deploy this backend before running the updated iOS conversation; old backends do not understand the new contract. Older apps continue to use the legacy path. No database migration is required. Regression tests use stubbed providers and cover the debug report's mixed answers, replacement loops, fabricated measurement, history replay and malformed risks. Actual model comprehension, recognition and conversational timing still require a device test; no production speedup or perfect understanding is claimed.
