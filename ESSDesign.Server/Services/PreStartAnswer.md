# Pre-Start conversation

`POST /api/pre-start/conversation-turn` accepts the current form snapshot, current question, transcript, up to 16 recent user/assistant messages, field statuses and basic selected-project context. It retains the existing assistant authentication, role policy and rate limit. No search of other projects is performed. No form is written by this endpoint.

The server uses the configured `OpenAI__PreStartModel` (default `gpt-4.1-mini`) and strict JSON-schema output. It validates typed operations, quoted user evidence, conditional details, counts, attendance limits and six risk rows. The response contains final patches with expected old values, status, action, target field and separate spoken segments. The app validates the whole batch against the current draft, including signatures, before applying it. A stale or cancelled response cannot overwrite newer edits.

Supported behaviours include answers across non-adjacent fields, additions, replacements, individual risk-row edits/removal, explanations, partial information, uncertainty, deferral, revisits and returning to an interrupted question. Original yes/no and numeric fast paths remain local. Signatures, photos, approvals and completed checks are never inferred from planned work. User corrections and explicit negative answers retain the existing conditional clearing rules.

The iOS app stores recent conversation and progress locally for the signed-in user and form, accepting it for at most 24 hours and only when it matches the current draft. Unsaved form changes are not restored from conversational memory. Deferred answers get one return pass; unresolved items remain visible for manual review. Pause, close, backgrounding, interruption and playback cancellation retain the existing controls.

The scaffold vocabulary covers scaffold components, tasks, stairs, bays/lifts and common recognition mistakes. `PreStart__ApprovedKnowledge` can supply maintained company-approved guidance; none is invented when this setting is absent. Selected-project metadata and current answers are context, not evidence of safety or compliance. Live company document retrieval, an autonomous safety adviser and speech-to-speech provider migration are not enabled by this change.

The existing `/api/pre-start/assistant-answer` endpoint remains compatible with older clients and the dedicated activity-dictation feature. Updated apps fall back to it only if the new endpoint is absent (404/405), not on malformed output, authentication failures or temporary model errors.

Validation: `dotnet test ESSDesign.Server.Tests/ESSDesign.Server.Tests.csproj -p:SkipClientBuild=true --filter FullyQualifiedName~PreStart`. These deterministic tests stub provider responses. The opt-in `scripts/evaluate-prestart.mjs --live` runs synthetic interpretation scenarios through a configured backend without calling the speech endpoint; it consumes OpenAI usage and may add reviewed generic phrase metadata. Physical-device testing is still required for recognition quality and perceived voice timing.
